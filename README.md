# dsh-workspace-sync

一个 DeepSeek Harness 插件。它把一台电脑上的 DSH 工作区，通过局域网直接同步到另一台电脑。


## 这是什么

DSH 是 DeepSeek Harness，一个本地运行的 AI 工作台。工作区就是 DSH 里存放对话、记忆、配置的那个文件夹。

你可能有主力机和出差机。这个插件让两边的工作区内容保持一致。

同步是手动的。你在面板点「立即同步」，或者在对话里调用 `sync_workspace`，才开始一次同步。插件不监控文件变化，也不是实时的。工作区是 agent 实时在写的，插件只在你要的时候动手，不会在干活中途突然改文件。

同步在局域网内走 P2P，两边机器直接对传，不经过服务器，也不经过中继。

现代 Mac 和 Windows 都行。Mac 对 Mac、Mac 对 Windows、Windows 对 Windows 都可以。三台或更多，依然是两两配对，一台一台对着同步。

三台以上时同步记录只有一份「上次同步」，多台机器同时改同一个文件，结果不保证正确。

## 安装

每台要同步的机器各执行一遍。

```sh
dsh plugin --profile web add git+https://github.com/Airls-bubble/dsh-workspace-sync.git
```

装完重启 `dsh web`，设置页左栏才会出现「工作区同步」分区。

卸载：

```sh
dsh plugin --profile web remove dsh-workspace-sync
```

## 第一次用

**第一步：配对。** 两台机器得先认识彼此。

- 机器 A 在面板点「生成配对短码」，得到一个 6 位数字。短码 10 分钟内有效。
- 机器 B 把短码输进面板输入框，或点「发现局域网设备」找到机器 A 后一键配对。

如果两台的局域网多播不通（比如不在同一网段），就改用面板「高级」里的完整配对码，以 `DSS1.` 开头的那一长串。把这个完整码通过你信任的方式发过去（聊天、AirDrop、U 盘都行），对方导入即可。

**第二步：确认目录。** 两台机器各自在面板里选定要同步的工作区根目录。每台选每台的，互不影响。

**第三步：第一次同步，定方向。** 这次两边还都没有同步记录，插件不知道该听谁的，所以要先定好哪边是「真源」。真源就是这次以哪边为准。

- `push`：以本机为准，覆盖对端。本机文件更全、更新时就选这个。
- `pull`：以对端为准，覆盖本机。对端文件更全时就选这个。

这一步叫播种（第一次同步，把一边的工作区整体搬到另一边）。播种之后就是双向同步。

也有自动的情况：如果一边的文件夹是空的，插件会直接照有数据的那边播种，不用你选。只有当两边都有数据、又没有任何同步记录时，才必须手动指定方向，否则插件会拒绝并让你确认。

## 日常使用

每次同步：在面板点「立即同步」，或对话里让插件跑 `sync_workspace`。

对话工具有三个。

| 工具 | 干什么 |
|---|---|
| `sync_workspace` | 执行一次同步。`peerId` 指定对端（配了多台时才要）；`seed` 设 `push`/`pull` 做播种；`confirm_conflicts` 为 `true` 才处理冲突；`background` 为 `true` 后台执行 |
| `sync_status` | 查本机身份、服务端口、当前工作区、已配对设备、上次同步报告。后台跑时，`syncing:false` 表示结束了 |
| `sync_pair` | 配对。`offer` 生成 6 位短码；`export` 出完整配对码；`import` 导入；`list` 看已配对设备；`forget` 删除某个对端；`discover` 列出局域网在线设备，对方若开着配对短码，可以直接一键配对 |

发现冲突时，插件只给一份计划清单，不动文件。你看完清单，确认 `confirm_conflicts:true`，才真正落盘。

## 同步规则

插件拿三条清单做比对：基线、本机、对端。

基线（上一次成功同步的记录，插件靠它判断哪些文件改过）。每次比对就是基线对着本机看改了没，再对着对端看改了没。

结果只有几种。

- 只有一边改了：直接把改动同步到另一边。
- 两边改的是同一个文件：冲突。

冲突讲究「两边都留下，谁都不丢」。

- 同一文件两边都改了：新的那份占原来的文件名，旧的那份改名为 `名字.conflict-<时间戳>.后缀`。两台机器上都保留这两份。谁新谁旧看文件的修改时间，时间完全一样时以本机为准。
  - 比如 `report.txt` 冲突了，旧版存成 `report.conflict-<时间戳>.txt`。
- 一边删了、一边改了：改的那边赢，删除不会覆盖修改。
- 删掉的文件都不真删，挪进本机 `.sync/trash/` 目录。之后能捞回来。

## 排除规则

默认同步工作区里所有文件。有两层排除。

**第一层：永远不同步，也不能配置。** 这些一律跳过。

- `.sync/`（插件自己的状态目录）
- 符号链接（一种特殊的文件快捷方式，跳过并记进报告）
- `.DS_Store`、`desktop.ini`、`Thumbs.db`（macOS 和 Windows 各自生成的系统杂项文件）

**第二层：排除规则，在面板「工作区」分区里编辑，一行一条。**

新装的工作区，默认三条：`.git/`、`node_modules/`、`*.tmp`。

规则写法：

- `name/` 排除这个目录，任意层级里有就排除
- `*.tmp` 按文件名匹配，`*` 是通配符
- `a/b/c` 排除这条路径及它下边所有内容

两条纪律。

- **两台机器的排除规则必须一致。** 范围不一样，插件会把「对端有、这台机器排除了」的文件误判成对端删了。所以每次同步前两边会交换规则指纹（规则的一种摘要），不一致就拒绝执行。第一次播种时，发起方的规则自动同步给对端。
- **把已同步的文件加进排除，是安全的。** 两边副本都原样保留，也不会传播删除。反过来，取消排除让它重新进范围，如果两边都有同名文件又没有基线记录，会按冲突处理。

有个例外：0.4 版之前同步过的老工作区，升级后沿用旧内置排除清单（`.git/`、`node_modules/`、`.wiki-state/`、`*.tmp`、`~*`），不换成前面那三条默认。升级不会改变你原有的同步行为。

`node_modules` 里装着各平台编译好的原生二进制，跨机器不通用，所以默认不同步它。Windows 上依赖跟着 `skills-lock.json` 各自重装一遍。

## 可选的配置

平时用面板就够了。想改默认值，可以写 row config，字段如下：

| 字段 | 默认 | 作用 |
|---|---|---|
| `workspaceRoot` | 启动目录 | 默认工作区根，面板里可改 |
| `port` | `27891` | 同步服务端口，被占用会自动换临时端口 |
| `deviceName` | 主机名 | 局域网里显示的名字 |
| `autoStart` | `true` | 启动 DSH 时自动起同步服务 |

## 数据在哪

每台机器各自存自己的状态，在 `~/.dsh/storages/workspace-sync.json`。里面是这台机器的身份、门禁令牌、已配对设备表。令牌是进门钥匙，这个文件别外传。

工作区根目录下有个 `.sync/`，放基线和回收站。它自己永远不会被同步。

## 安全

先说清楚。同步走的就是局域网明文 HTTP，没有 TLS（传输加密）。这是局域网场景下的取舍。

门禁令牌（配对时自动交换的一串钥匙）只管进门，不负责加密。未配对设备能访问的只有 `/sync/ping`（一个只报设备名的接口），别的路由一律拒绝，返回 401。

它能挡住陌生人，不让别人往你工作区写文件。但同在一个 Wi-Fi 的人，能看到网络上流过的数据。介意就别在公共网络里同步敏感内容。

令牌和配对码是同一把钥匙。泄露配对码等于把工作区写权限交出去。通过靠谱的渠道交换，别发公开频道。要吊销，用 `sync_pair forget` 或在面板撤销对端。

短码 5 次输错会锁 30 秒。

笔记本带去公共网络时，同步服务也会在那个网络里监听。想彻底关掉，可在 row config 里设 `autoStart: false`，用到再开。

## 开发与测试

```sh
npm install
npm test
```

`npm test` 跑全部测试。`pretest` 是安装后自动跑的前置脚本，它会先重建仓库里 `@deepseek-ai` 的 peer 链接再测试，别删。

插件依赖 DSH 本体提供的 `@deepseek-ai/*` 包。如果插件启动后休眠、日志说「dsh-tools 不可解析」，跑一下仓库里的 `scripts/link-peers.js`，然后重启 `dsh`。

测试里有一个真实回环：两个服务、两个临时工作区、真 HTTP，覆盖播种、合并、删除、冲突、门禁的完整流程。
